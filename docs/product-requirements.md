# ComfyPilot 产品需求

日期：2026-10-27（Asia/Shanghai）

状态：根据用户最新约束修订的设计基线，功能尚未实现。

ComfyPilot 是在当前项目目录运行、供外部 AI Agent 操作的创作与审片工作台。核心模型保留通用扩展能力，第一版集中处理 ComfyUI 视频人物替换。发布边界见[首版范围与验收](mvp-scope.md)，实现约定见[架构设计](architecture.md)，参考方案与后续交互见[技术调研与分期](research-and-roadmap.md)。

## 1. 用户与产品目标

目标用户已经在本机使用 Claude Code、Codex 等 Agent 工具，拥有或可以连接 ComfyUI。模型调用、对话上下文与 Agent 本身由现有工具提供。

用户主要做两件事：提出创作要求、审阅产物。Agent 负责初始化、配置执行端、准备素材与依赖、编排运行、读取反馈、安排返工和交付。平台保存事实、执行确定的任务，提供实时审片与生产监控界面；项目服务运行期间，后台持续监测和自动收片，不要求用户手动维护数据库或启动服务。

来自旧项目的经验：

| 已观察的问题 | 本项目的处理 |
| --- | --- |
| 生成完成仍可能漏换人物、构图偏移 | 区分执行完成、技术合格、用户审片和正式采用 |
| 后来的失败候选影响已采用版本展示 | 候选不可覆盖已有采用关系 |
| 提交响应丢失后重投可能重复消耗 GPU | 先保存意图，再提交；结果不明先对账 |
| 不同实验的输入、参数和环境容易混淆 | 每次运行冻结实际输入、工作流与执行端快照 |
| 会话切换后需要重读大量记录 | 提供项目上下文摘要、未处理反馈和事件游标 |
| 整批完成后才审片会放大返工 | 每段完成即进入待审列表，返工反馈可阻止后续派发 |

这些是前期只读分析所得的设计依据，不代表新产品已经验证。

## 2. 已确认的产品约束

| 事项 | 确定规则 |
| --- | --- |
| 服务作用域 | 每个当前项目目录一个实例；不建立全局服务或全局项目配置 |
| 项目根目录 | Agent 显式传入绝对路径；不猜测 MCP 进程的工作目录 |
| 数据位置 | 所有平台配置、元数据和资源在当前项目内；程序与 MCP/Skill 安装位置不等于项目状态位置 |
| MCP | 宿主可以提前启动进程，但桥接器待机、不探测平台；由 Skill 指导 Agent 显式启动、连接、断开、停止 |
| 平台访问 | 无账号，默认无需密钥，默认回环监听；局域网监听由用户指定 |
| 执行端 | 本机与远程 ComfyUI 均支持，可保存多个；初始化时由 Agent 询问，随时可改 |
| 调度 | 按用户指定执行端或明确路由规则；不擅自更换目标、转用云服务或扩大次数 |
| 自定义资源 | 用户可在项目内放工作流、节点源码与说明；Agent 能发现、检查和安装 |
| 首要体验 | 用户提需求，Agent 操作，审片同时查看生产状态，意见进入后续任务 |
| 监测与收片 | 项目服务内的常驻程序负责，不依赖浏览器或 Agent 在线，不新增持续调用大模型的监控 Agent |
| 平台边界 | 不内置 Agent 会话或模型账户，不接管宿主 MCP 生命周期 |

如远程 ComfyUI 自身要求认证，可保存可选的项目私密连接配置；这不引入 ComfyPilot 账号或平台密钥要求。

## 3. 术语与模块边界

| 术语 | 含义 |
| --- | --- |
| 项目 Project | 当前文件夹及其配置、任务、资源和状态；首版不再另设多工作空间层级 |
| 执行端 Target | 一个 ComfyUI 实例；避免与自定义节点混称“节点” |
| 业务模块 Module | 面向用户的能力，例如人物替换、文生图、图生视频 |
| 工作流配方 Recipe | 具体工作流与输入、参数、输出、依赖和适用环境的声明 |
| Skill | 告诉 Agent 何时调用哪些工具、怎样处理反馈和异常的操作说明 |
| 自定义节点 Custom node | 安装到 ComfyUI Python 环境中的扩展代码 |
| 业务节点 Block | 后续简化画布中的高层步骤，例如人物替换或审片；可封装一个配方 |
| 任务 Task | 有目标和验收标准的创作单元，可对应一个视频片段 |
| 运行 Run | 一次确定的外部执行尝试，固定输入、配方、参数及执行端 |
| 产物版本 Version | 不可变文件及其来源；技术合格、审片结果和采用关系分别保存 |

模块不能只是几个分类标签。每个模块需要说明可做什么、输入输出、配方、依赖、检查方式、反馈形式和 Agent 操作步骤。平台提供少量实测预设；项目可以添加同一契约的配方和资源。首版不开放任意动态服务端代码插件。

## 4. 典型协作流程

### 4.1 首次使用与连接

1. 用户在当前文件夹提出视频处理需求并调用相应 Skill。
2. Agent 显式指定项目根目录；尚未初始化时，询问 ComfyUI 地址、默认执行端、远程管理条件及监听方式。
3. Agent 初始化项目配置，启动项目服务并连接 MCP 桥接器，给出审片页面地址。
4. Agent 检查模块、配方和目标能力；发现缺少节点、模型或素材传输能力时，给出具体缺项并处理。
5. Agent 把需求整理为片段任务、参考素材、执行目标、次数范围与审片标准，在已有用户指示范围内执行。

安装 MCP 或枚举工具本身不会初始化项目、探测 ComfyUI 或启动服务。用户不需要手动启动平台。

### 4.2 视频人物替换与实时审片

1. 导入原片、人物参考图和已知片段范围；平台保存独立的受管理副本与哈希。
2. Agent 选用可用配方，准备片段，保存输入、参数和输出规格，创建运行。
3. 平台自动跟踪生成、收片和检查，展示各阶段及异常；每段合格结果立即显示在待审列表，无需 Agent 逐次触发收片。
4. 用户可以在后续片段生成期间对原片、候选和已采用版本同步审阅，按时间范围和截图圈选反馈。原片与渲染片共用播放/暂停和进度条，缓冲联动，支持按实际帧率前后逐帧查看。已知映射换算偏移；其他情况按输入片段相对时间联动，并说明“按时间对照，不保证动作逐帧一致”。
5. 用户选择“需要修改”时，平台立即挂起受影响方案尚未提交的步骤；在途任务继续收集。
6. Agent 读取反馈、提出修改并按已有指示安排局部返工。新运行生成新版本，合格后再次待审。
7. 用户点击“通过并采用”，或在对话中明确指定采用，由 Agent 代录该决定；交付使用明确的采用版本清单。

“实时”指状态及时更新和逐段可审，不承诺视频尚未生成完成时就能播放完整片段。

### 4.3 自定义资源与多个执行端

用户把资源放到项目约定目录，Agent 刷新资源目录，取得说明、配方和依赖报告。项目资源与内置预设可并存；同标识覆盖必须显式配置，不能按文件名静默替换。

工作流在项目里存在，不等于在所有执行端都能运行。节点安装、模型、输入输出适配与测试结果按执行端分别记录。只有 HTTP 地址时不能承诺远程安装 Python 扩展；Agent 需使用用户配置的 SSH、终端或其他管理通道。

任务按用户指定的 target_id 执行；地址或默认目标变化只影响后续方案，不迁移已有运行。首版项目总生成并发为 1，支持不同步骤明确选择不同执行端。

### 4.4 ComfyUI 素材清理

用户提出清理要求，Agent 获取本项目在指定执行端的素材清单、占用和候选删除原因。平台先生成清理计划，再在用户已明确的范围内执行；已有明确指示不需要逐文件重复确认。

只清理本项目管理的输入、输出和临时副本，不清理模型、节点、其他项目或归属不明文件。运行中、待核对、待收集、待审或仍被计划引用的素材受到保护。远端结果必须先有本地已验证副本。执行前重新检查引用，返回逐项结果与估算/实际释放情况。

第一版不删除本地正式产物版本，不做定时自动清理或全盘扫描。

### 4.5 审片同时监控与调整工作状态

1. 用户在播放器侧栏查看平台/Worker 心跳、各执行端连接、当前片段、生成阶段、节点进度、队列与收片状态，底部查看活动记录。
2. 监控标明数据来源、更新时间和可用性；断连显示最后已知状态已过期，缺失指标显示未知或不支持。
3. 用户可以告诉 Agent「先暂停后续生成，把已完成的收回来，后面的改用第二个执行端」。
4. Agent 通过 MCP 读取同一份状态，暂停派发、查询或恢复收片，为未提交步骤建立新的方案修订，并在原指示或新增指示范围内恢复。
5. 面板同步显示控制结果、受影响任务与阻塞原因；监控刷新保留播放位置、当前审阅版本和未提交批注。

平台服务停止时监测和收片随之停止；再次启动接续对账和收片。MCP 待机、工具枚举或 Agent 会话退出不启动额外监控连接，也不构成平台停止指令。

## 6. 执行与决策规则

### 6.1 用户指示与 Agent 自主操作

用户明确的目标、输入范围、执行端、最大提交次数和暂停条件可构成执行指示，Agent 结构化记录后可连续操作。普通执行不要求用户另开网页逐项审批。

缺少关键条件时由 Agent 询问；改变目标、突破次数或更换未允许的执行端需要新的用户指示。服务按已记录范围限制执行；Skill 负责解释和协作，不替代服务中的次数、引用与状态检查。

最终审片结论来自用户。Agent 的技术判断与视觉观察单独记录；对话代录需要注明来源和用户原意。无账号模式下，这些记录用于协作追溯，不声称完成了身份认证。

### 6.2 冻结输入，保护在途任务

每次运行保存配方版本、最终 API 图、输入版本与顺序、参数、模型引用、环境信息和执行端快照。磁盘文件、默认配置或新配方的变化不改写已有运行。

方案内容改变生成新修订。新指示替换旧指示时，旧修订未提交的步骤停止派发；已提交任务继续对账和收片。停止平台不等于中断 ComfyUI。

### 6.3 状态和来源

任务、运行、技术检查、审片评价、采用关系各自保存。进度 100% 不等于产物合格，合格不等于用户采用。后续失败不清除原采用引用。

提交先存意图，后调用外部接口；结果不明进入“待核对”，阻止相关调度，不自动重试、切换执行端或生成新种子。收片恢复不会再提交生成。

### 6.4 反馈和协作冲突

反馈绑定具体产物版本。旧版本反馈不自动迁移、也不自动阻断新的修订；需要影响当前方案时明确关联。

“需要修改”和“停止后续任务”会在平台侧阻止相关方案继续派发，不依赖 Agent 当时在线。普通备注不自动停止批次。Agent 标记已处理表示已提交修复说明，用户审阅后才能记为验证通过。

Agent 和网页更新同一对象时检查修订号，冲突保留双方草稿，不采用后写覆盖。用户改参数先形成草稿，不静默修改正在执行的运行。

### 6.5 监控、自动收片与控制边界

- 监测、对账、收片和已确定任务由后台程序持续处理；AI Agent 负责解释异常和调整方案。首版不依赖额外的大模型监控进程。
- 生成进度按执行端实际事件展示。支持采样进度时展示节点步数；其他阶段展示状态与已耗时，不推算无依据的整体百分比或剩余时间。GPU 利用率、温度、远端 CPU/磁盘与完整日志按额外采集能力提供。
- 暂停生成派发不停止监测、在途对账或自动收片。传输临时失败只重试收片；空间不足等问题显示阻塞，确定的媒体检查失败保留证据，不把收片重试转换成生成重试。
- MCP 与网页读取同一套项目状态和事件；控制命令记录来源、结果及对象修订，重复命令不重复执行。恢复派发仍受用户范围、次数、review_hold 和待核对状态约束。
- 取消限尚未建立提交意图的步骤；参数、素材或目标调整生成新修订，已提交运行及其目标快照保持不变，不调用 ComfyUI 全局中断或清空外部队列。
- Agent 在线时可查询或有限等待事件；会话结束后由后台保存状态和待处理事项，首版不承诺 MCP 自动唤醒离线会话。

## 7. 首版信息架构与成功标准

首页突出待审片段、需要处理的反馈、当前执行和阻塞原因。任务详情以原片/候选对比为主，侧栏展示反馈、采用版本、Agent 说明和可折叠监控区，底部提供队列与活动记录。监控区包含平台与执行端健康、生成/收片阶段、可获取的设备与空间信息；刷新不打断播放、不切换审阅版本、不清空批注草稿。模块、执行端、资源与存储管理作为辅助入口。

首版目标是以下可重复验证的行为，当前尚无测量结果：

- 本机与远程各有一套真实视频人物替换链路，完成准备、生成、逐段审片、返工和采用。
- MCP 宿主启动时平台仍离线；调用 Skill 后 Agent 能在指定项目完成启停和连接。
- 两个项目同时运行时，端口、配置、数据库与素材互不串用；同项目重复启动复用原实例。
- 换 Agent 会话后能准确读取当前目标、采用版本、待处理反馈、活动运行和执行范围。
- 提交响应丢失、服务退出或收片中断后，无证据证明可重试前的额外生成提交数为 0。
- 正常本机/局域网环境中，业务事件持久化后页面 3 秒内更新；本地合格片段无需等待整批完成即可播放。
- 健康与基础系统指标首版默认每 5 秒采集；距最后有效采集满 15 秒标记过期，缺失或不支持的指标不显示为零或正常。
- 关闭浏览器或退出 Agent 会话后，运行中的项目服务仍自动收片；收片恢复不增加生成提交，也不重复登记版本。
- Agent 通过 MCP 查询的运行、队列、反馈挂起和收片状态与面板一致；调整未提交步骤可追溯，不能改写在途任务。
- 用户提出需要修改后，相关方案尚未建立提交意图的步骤不再提交。
- 清理不触及保护项；移除远端副本后，本地审片与已采用结果仍可访问。

后续以业务流程图和新媒体模块扩展，保持项目、任务、运行、版本、反馈这些核心模型稳定。首版不额外建设一个完整文本协作应用来验证通用性。
