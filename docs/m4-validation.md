## 时延、新鲜度与浏览器复验

业务测试在同一 macOS 时钟下，比对数据库 business_events.created_at 与真实浏览器 MutationObserver 首次看到唯一反馈标记的 Date.now。没有轮询测试截图来推断时延，没有改写页面快照或数据库制造成功。

- 本机五次：231、21、820、615、407 ms；LAN 地址五次：783、577、371、152、968 ms，全部低于 3 秒。该小样本不代表长期负载上界。
- 真实目标相邻采集间隔 5.015、5.010、5.016、5.018 秒；每条 expires_at-observed_at 为 15 秒。采集周期包含请求/调度耗时，不宣称实时系统精确到毫秒。
- 暂停本次独立项目的 Worker，持续读 API 并观察页面；指标年龄 14.960 秒为 fresh，15.067 秒为 stale，保留来源/时间。恢复 Worker 后重新采集，不改 Run 状态；浏览器观测到过期及恢复，播放/草稿不变。精确阈值另由可控时钟回归验证，实际 API 观测误差取决于轮询周期。
- LAN 页面实际键入草稿，事件/指标刷新期间记录两个 video DOM 身份、播放状态和 emptied 计数；草稿、候选和播放器保持，持续播放且 emptied=0。原 M3 记录另覆盖真实在途停止/重启的 1.25 秒位置和草稿保持。主动刷新整页、关闭标签后的草稿持久化不属于此承诺。

本轮浏览器回归发现并修复两处缺陷：普通 HTTP LAN 缺少 crypto.randomUUID 导致批注输入报错；监控五秒缓存使已过期采样暂时仍标 fresh。前者用 getRandomValues 生成 UUID v4，并覆盖全部五个调用位置；后者复用过期计算、缓存命中时仍刷新有效性与 Worker 心跳判定。新增失败测试先复现再通过，重新构建并安装验证。
