# 独立执行端切换验收

日期：2026-10-29（Asia/Shanghai）。对应 M3/3.8、AC-05 与 AC-40。复用已完成[独立安装验收](h3-install-validation.md)的测试环境；媒体、地址、完整回执与原始日志留在源码外，不进入公开文档同步。

## 环境与授权

两个真实 ComfyUI 实例具有不同服务地址、容器身份、核心/venv 和 input/output 目录；只读共享四个固定模型。两者均为 ComfyUI 0.38.0 固定核心，Python 3.13.15 / PyTorch 2.13.0+cu130，共用一张 RTX 3090 / 24 GiB，按用户授权错峰运行。该验证覆盖独立实例切换，不代表两台物理 GPU 或并行渲染。

平台使用源码外 wheel 安装版，在新 UUID 创作项目中通过真实 stdio MCP 操作。原审片项目、用户采用作品及旧版本不改。采用 H3 人物替换配方，固定原片/参考图哈希、768×448、24 fps、124 帧、20 步；初始授权允许 A/B 两目标及 seed 42/43，累计最多两次提交，失败停止，不自动采用。

## 实际过程与判定

1. 原目标 A 收到第一项生成，平台已持有回执且 Run 为 running。在此期间暂停派发和原方案，将项目默认目标改为 B，再为同一任务建立并生效 B 修订。新修订复用原授权根，沿用原素材/配方，仅在已允许范围内改目标及 seed。
2. B 继承暂停并入队一次，重放原入队命令返回同一回执。此时 A 仍在途，B 没有 intent；累计额度为已用 1、排队 1、上限 2。A 的 intent、目标/资源快照、实际图、输入副本和 prompt_id 均与切换前一致。
3. 即使项目默认目标和有效方案已指向 B，平台仍按 A 的冻结目标读取原 history 并下载结果。A 成功收片且规格/完整解码检查通过，只有一个 ready 版本；B 仍未提交。
4. 确认 A 队列为空后停止原容器，启动独立 B 并重新探测、预检；B 没有 A 的 history。显式恢复 B 方案及派发后，第二项由 B 收到，产生不同的真实 prompt_id，并从 B 自动收片。
5. 最终恰有两项成功 Run、两个 ready 版本，两个方案共用一个授权根，累计使用 2。B 执行全程，A 已完成 Run 的完整记录及版本保持精确一致；A 的冻结数据与运行中基线保持一致。没有迁移、重提或替换旧结果。

未授权目标、seed=44、变更输入哈希均返回 mandate_exceeded；将原授权上限从 2 扩为 3 返回 new_instruction_required。两次提交完成后，再排队新步骤被 mandate_exceeded 拒绝，业务 revision、Run、额度和事件游标均不变。不能通过修订重置累计额度。

## 自动化回归与复验

新增 tests/test_target_switch.py，使用两个独立 HTTP/WebSocket 协议端和各自输入/输出根复跑同一流程。两端故意返回相同 prompt_id，验证对账仍按冻结目标隔离，暂停继承、旧 Run/版本不变、累计额度与第三次拒绝均成立。协议端测试不计作真实 GPU 证据；上述两次生成另由真实 history、桥接文件及完整解码证明。

复验时先固定两目标及原始授权，保存 A 在途的 intent、step、target_snapshot、resource_snapshot、materialized、receipt；切换后持续逐项比较。待 A 收片后再保存其完整 Run 和版本，直到 B 完成持续精确比较。记录两端 history、收片来源、独立输入副本和累计用量；拒绝请求前后比较完整执行快照。两端共用 GPU 时须先等原端收片及空队列，再切换容器，不能将停机失败算作切换成功。

make check 的 Ruff、格式、Biome、TypeScript、Web 测试/构建与 238 项 pytest 通过，2 项大文件压力测试按既定配置默认跳过；本轮未改运行代码、接口或数据库结构。

最终 wheel 为 306400 字节，SHA-256：`0f74bcedb0927b771adb30316cab8293f48bd2596a6412cd5fc58925c32f9a78`。源码外新 venv 使用带哈希运行依赖安装，逐文件核对包内容，CLI/API/独立 Worker/Web 静态资源、59 个真实 stdio 工具及原目标桥接只读探测通过。真实换端使用前轮最终安装版，其运行代码与本轮相同。

## 恢复与边界

测试结束停止独立 B，恢复同一原容器并核对健康、空队列、桥接能力，并复核平台已持久保存的原 history。33 个既有素材/配置保护文件与四个共享模型的大小及 SHA-256 保持，两个容器的身份、镜像和挂载不变；原核心工作区保持干净。两端本次 6 份输入/输出文件的大小和哈希与平台记录一致，本地导入原件未变。新增测试素材和结果保留在各自新 UUID 命名空间，未清理原文件。原容器重启后 ComfyUI 内存 history 已清空，平台持久保存的成功凭据、Run 和版本保持，没有触发补投。

本轮仅完成技术验收，不代替用户对新候选的审片或采用。双宿主首次信任/人工批准、交互退出及 Linux 真实双宿主仍保留；模型从零下载/恢复、其他硬件和长期负载未覆盖。正式发布状态见 [M4 联合验收](m4-validation.md)。
