# M3 审片、监控与 Agent 联合验收

日期：2026-10-28（Asia/Shanghai）。本轮使用用户授权的原片与参考图，H3 配方固定 768×448、24 fps、124 帧、20 步。媒体、服务地址、原始回执与宿主记录保存在源码外的独立创作项目，不进入公开仓库或看板同步。

## 环境与判定边界

macOS / Python 3.12.13 平台通过协议 1 素材桥接连接远程 ComfyUI；Linux / Python 3.12.3 平台通过实际 input/output 目录连接同机 ComfyUI。两平台从 wheel 安装，API/Worker 在源码外运行，顺序使用同一 RTX 3090 / 24 GiB 实例。目标核心、模型锁与媒体工具条件见 [H3 验收](h3-validation.md)。

真实 GPU 结果、替身故障测试、浏览器交互和实际 LLM 宿主分别留证。标准接口没有的温度、GPU 利用率、远端磁盘、完整日志显示不支持；未收到节点回调时阶段未知，不估算整体百分比或 ETA。监测采样有来源、时间及有效期，断线保留旧数据并显示过期/重连。

## 已验证的协作过程

1. 创建 A、B 和一个后续 A 的串行方案，固定素材、参数与目标，最多三次提交。A 自动收片后即可播放，此时 B 仍在真实生成；页面的播放、反馈和监控不要求用户保持 Agent 在线。
2. 全部 MCP/LLM 会话退出后，在浏览器为 A 保存测试反馈及 0.75 秒截图圈选。反馈与任务挂起同事务持久化，页面约 284 ms 后显示更新；未提交的第三步保持无 intent，B 的原任务继续完成。该反馈明确标注为自动化链路测试，不代表用户的审美意见。
3. Claude Code 2.1.302 / GLM-5.3 新会话读取项目内随包 Skill，通过真实 MCP connect_service、get_context 和 propose_plan 提出一个返工草稿。逐条工具记录与草稿内容经主进程复核：只改 A 的后续候选，沿用 seed=44、原素材/规格、原授权根和累计额度，没有自行执行、扩大范围或代替用户采用。
4. MCP 暂停旧方案并取消指定无 intent 步骤，生效反馈关联的新方案。暂停随修订继承，反馈成为 addressed，解除相应任务挂起；显式恢复后派发一次返工。B 的 intent、目标快照和最终图哈希保持不变。三次生成结束，原授权累计用量为 3，剩余为 0；被取消的等待项未占用提交。
5. 用户实际审阅 A，确认只替换 C 位主角并明确采用。Agent 依据这次对话代录采用，保存用户原话及 agent 来源，交付清单仅包含该已采用原件和来源。返工新候选到达后，原采用仍保持；技术 ready、addressed 和用户 verified/采用分别处理。
6. 真实返工在途时停止并重启本地平台，ComfyUI 按原回执继续。浏览器自动重连前后保持原候选、同一播放器 DOM、1.25 秒位置和未提交文字草稿；重启默认暂停新的派发，旧任务继续对账并自动收片。监控更新不会自动切换候选。

7. Linux 平台另提交一次真实生成。原回执在途时用受限 PATH 重启平台，目标完成后收片阻塞为 media_tools_missing，尝试次数为 1，没有 ready 版本；恢复工具后用 MCP resume_collection，重放同一请求得到相同回执。最终只有一个检查通过的版本、一个目标 history 回执，累计提交为 1；intent 与原 prompt_id 均保持，Range 206、完整解码和浏览器 124 帧播放至结束通过。

首次 LLM 只读尝试因读取安装目录外部文件受限，没有成功读取 Skill；不计为 Skill 验收。将随包目录完整放入该创作项目的宿主 Skill 路径后，新会话实际读取成功。配置密钥仅经子进程环境传递，未写入平台配置、提示词、记录或仓库。此证据只覆盖本次接续场景，不替代 M1 双宿主完整矩阵。

## 复验方法

- 按 [Agent 接入](agent-setup.md)安装 wheel、完整 Skill 与待机 stdio MCP；显式指定独立项目和执行端。检查 get_context 的根目录、有效配置名、方案、累计授权、候选、采用与未解决反馈。
- A ready 后在真实浏览器播放，确认 B 在途；保存绑定版本/时间的截图反馈，比较业务事件持久时间与页面到达时间。Agent 离线时核对后续运行没有 intent。
- 用新会话只提案，复核后再按原指示暂停、取消、激活、恢复；所有命令保存 command_id、revision/event_id 与剩余门禁。网络结果不明时重放原请求；明确 conflict 后回读并使用新 ID。
- 在途重启平台，核对原 prompt_id、intent、用量与版本唯一性。浏览器在同一页面等待自动恢复，检查播放位置、选择、草稿及新鲜度；本项不承诺手动刷新整页或关闭标签后的草稿持久化。
- 收片工具恢复只调用 resume_collection，不创建新 Run 或绕过平台提交。使用同一请求验证原回执重放，检查唯一版本、Range 206、完整解码和浏览器实际播放。

## 本轮缺陷修复

- 片段标签改为稳定的 segment_id（旧数据回退输入素材或 Run 标识），新片段到达不再改变已有片段的显示编号；选择仍由用户持有。
- get_context 使用当前有效配置中的项目名称，与项目概览一致；配置更新后的回归测试已先复现旧名再验证修复。
