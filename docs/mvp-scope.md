## 1. 交付形态

交付一个可安装的本地软件包，包含项目服务、Web 静态资源、独立 Worker、待机 stdio MCP 桥接器、Agent Skill 和少量实测模块资源。用户安装后通过 Agent 使用，无需手动启动服务。实际包名、命令与宿主配置在实现时确定，本文不提供尚不存在的启动命令。

一个项目目录对应一个服务实例。所有平台配置、状态和资源保存在该目录；不增加全局平台服务、项目注册表或全局执行端配置。MCP/Skill 的宿主安装属于工具安装，不承担平台状态存储。

默认回环监听、无账号、无需平台密钥。按用户要求可以监听局域网供审片。MCP 控制与服务管理仍通过本机连接进行。

M1/1.6 已完成方案、指示、幂等入队及同事务提交门禁的替身验证；当前没有实际生成派发；M2/2.1 已接入资源声明校验和冻结，素材上传与提交由后续 M2 接入。

M1/1.5 的能力、超时、缺项、断连和节点事件已使用标准 HTTP/WebSocket 替身验证；真实远程 ComfyUI 的连接、目录与基础监测已通过，真实渲染进度事件与收片仍待后续生成验收。

M1/1.3 阶段验证使用官方 SDK 的真实 stdio 客户端，覆盖服务未运行/已运行时的握手与枚举零项目访问、零网络连接，以及显式连接、旧实例拒绝、双项目/双桥接器和 MCP 退出后的服务存活。该阶段不替代 M1/1.7 的实际双宿主/Linux 验收，也不代表 ComfyUI、收片和审片已验收；当前工具见 [README](../README.md#stdio-mcp)。

## 3. 工作流、自定义节点和远端兼容

每份可执行配方必须提供：

1. 模块、配方 ID 与版本、用途、示例和已知限制。
2. 工作流原件；可执行 API 图；可调整参数 schema、输入槽位和输出读取规则。
3. 自定义节点来源和固定版本、Python 依赖、模型名称/来源/许可及已知校验信息。
4. Agent 安装步骤、目标环境要求、是否需要重启、安装后验证和回退说明。
5. 输入顺序、裁剪/偏移、输出媒体规格和技术检查规则。

用户可以存放 ComfyUI 画布 JSON、API JSON 和节点源码。画布原件可以入库，但只有完成经过验证的转换、绑定和目标预检后才标记为可执行；不靠猜测 widgets 数组或子图编号转换。Agent 可借助官方工具和目标环境处理，不要求用户手工编辑 JSON。

工作流与节点资源进入项目目录后，通过显式刷新发现并计算版本；执行前冻结资源快照。发现、依赖已安装、目标预检通过是不同状态。预设与项目配方分别标明来源；覆盖使用显式映射。

| 能力 | 本机 ComfyUI | 远程 ComfyUI |
| --- | --- | --- |
| 状态与提交 | HTTP/WebSocket | HTTP/WebSocket |
| 基础监控 | 接口可用的设备/显存信息、队列和执行事件 | 同样通过标准接口采集，缺失项明确标记 |
| 详细主机指标 | 仅在有额外采集能力时提供 | GPU 利用率/温度、CPU/磁盘及完整日志不作为标准 HTTP 连接的保证 |
| 素材输入/输出 | 受管目录适配器 | 实测原生接口，或受限素材桥接扩展 |
| 视频通用传输 | 配置后的受管目录 | 首版配套素材桥接扩展，支持流式视频上传/下载 |
| 素材物理清理 | 受管目录删除与引用复核 | 素材桥接扩展删除与引用复核 |
| 节点/模型安装 | Agent 使用本机终端和目标环境 | Agent 使用已配置管理通道；只有 HTTP 时返回缺少安装能力 |
| 仅有标准 HTTP 接口 | 可使用已实测的媒体配方 | 按实际能力降级，不宣称通用视频传输或清理可用 |

素材桥接扩展是本项目拟交付的小型 ComfyUI 扩展，仅管理专属项目素材子目录；不提供任意 shell、包安装、全盘删除或模型管理。远程首版完整验收包含该扩展由 Agent 安装和探测。远程环境不允许安装时，保留标准 API 的已知能力并清楚显示限制。

首发至少锁定一套人物替换配方，在本机和远程环境各完成真实测试；记录 ComfyUI、节点、模型引用、FFmpeg 和扩展版本。平台本机至少验收 macOS 与 Linux 的生命周期；其他系统不以未经测试的“跨平台”描述发布。

## 4. 执行与审片的明确语义

- 一个步骤必须有确定执行端。默认目标可由用户在初始化时指定；多目标顺序计划仍遵守项目生成并发 1。
- 用户已有指示允许的配方、参数和次数内，Agent 可连续执行；范围扩大前重新取得指示。
- 外部提交前预留额度并保存意图；提交不明也占一次额度，不自动重试。
- 新方案不改写在途任务。停止后续任务、需要修改和停止平台，都不调用 ComfyUI 全局中断。
- 启动恢复优先核对原任务、收集已有结果；不把无 queue 记录当作未提交证明。
- 每段结果完成持久登记和必需检查后立即待审；其他片段可继续生成。
- 对当前有效方案的“需要修改”挂起其未提交步骤；旧版本普通反馈不自动影响新方案。
- 暂停结果与提交意图建立使用同一状态检查边界：已保存意图的任务按在途处理，未保存的不得继续派发。
- 网页或用户在对话中明确“通过并采用”均可记录；Agent 自己的质量评价不能自动成为用户结论。

导入视频采用流式复制与哈希。单文件默认上限：视频 2 GiB、图片 50 MiB、工作流 5 MiB；初始化可在项目配置中调整。收片前检查可用空间，原片、原始输出和播放代理分别记账。H.264 MP4 为首版视频预览基准；其他编码按兼容清单决定生成代理或提示不支持，代理不能覆盖原始文件。

### 4.1 监控面板

播放器侧栏提供可折叠监控区，底部展示队列和活动记录；监控更新保留播放位置、审阅版本与批注草稿。平台服务启动且执行端启用后开始采集，暂停派发时继续监测；MCP 待机不产生采集请求。首版由 Worker 内的常驻程序处理，不增加大模型监控 Agent。

健康与基础系统指标默认每 5 秒采集，距最后有效采集满 15 秒标记过期；字段标明来源、采集时间和可用性。没有进度事件或附加主机采集能力时，展示阶段/已耗时与未知或不支持，不补造整体百分比、剩余时间或指标零值。业务变化仍遵守持久化后 3 秒内更新目标。

### 4.2 自动收片与 MCP 控制

外部成功证据触发自动收片，面板/MCP 可区分等待输出、传输、校验、准备预览、登记、可审、等待重试、阻塞和失败。传输显示已传字节；总大小只有可知时才展示。临时网络或读取错误最多 3 次额外退避重试，耗尽后保持可恢复阻塞；空间不足阻塞，确定的媒体检查失败终止并保留证据。

Agent 可通过 MCP 查询状态、暂停/恢复派发、取消未提交步骤、修订后续方案及恢复收片。取消仅接受 queued 且无 intent 的运行；恢复收片仅处理已确认成功的原 Run，不消耗生成额度、不重新提交生成。服务/方案的普通恢复不自动清除 review_hold 或待核对限制，参数与执行端变更通过新方案生效。

工作状态变更命令使用 command_id、expected_revision 和原执行范围，返回应用结果、受影响对象和事件引用；重新读取即可在面板和 MCP 核对。Agent 离线不影响已有确定任务与自动收片，MCP 不保证主动唤醒离线会话。

| AC-32 | FR-13 | 有节点进度事件时展示实际步数；无事件、模型加载或节点长时间执行时展示阶段/已耗时；不伪造整体百分比、ETA 或仅因无进度而重投 |
| AC-33 | FR-13 | 验证健康指标 5 秒采集及距最后有效采集满 15 秒过期；断连后显示来源/时间和最后已知状态，重连读取快照并补读业务事件，不把断连判为生成失败 |
| AC-34 | FR-13 | 在仅标准 HTTP/WebSocket 的目标上显示可用信息；额外 GPU/CPU/磁盘或完整日志缺失时标记未知/不支持，不显示为零，不自动开启 SSH 或安装采集器 |
| AC-35 | FR-14 | 浏览器关闭、Agent 与 MCP 退出而平台仍运行时，自动完成收片到可审；各阶段、已传字节和可知的总量可查询，监测心跳不被大文件处理阻塞 |
| AC-36 | FR-14 | 注入持续临时传输错误，最多 3 次额外重试后显示阻塞；修复后重复调用恢复收片，原 Run/输出槽位仅登记一次，额外 POST /prompt 和生成额度消耗均为 0 |
| AC-37 | FR-14 | 注入空间不足/预览工具缺失时阻塞，原始媒体确定解码失败时终止并留证；未满足必需检查/预览条件不进入可审，恢复收片不绕过检查或触发新生成 |
| AC-38 | FR-15 | MCP 获取平台/执行端、队列、运行和收片状态，与面板共享业务对象/修订及带时间的监测值；控制返回 command_id、应用结果和事件引用，重复命令不重复执行 |
| AC-39 | FR-15 | Agent 暂停方案、取消 queued 无 intent 步骤再恢复；在途继续收片，无 interrupt/清队列；恢复不清除 review_hold、待核对或次数限制，过期 revision 返回 conflict |
| AC-40 | FR-15 | 按用户指示暂停后续生成并收回已完成结果，再为未提交步骤改参数/素材/执行端建立新修订；原 Run/回执/采用版本不变，未允许目标或超范围请求被拒绝 |
