# 实时审片与协作

平台保存业务状态后，在同一 SQLite 事务中追加单调递增的业务事件。`GET /api/state` 在同一读取事务中返回业务修订、事件游标、任务、方案、运行和可审版本。`GET /api/events?after=0&limit=50` 按游标补读，每页最多 100 条；返回的 cursor 是本页实际读取位置，has_more 表示仍需补读。

`GET /api/events/stream?after=<cursor>` 提供 SSE。持久变化使用 business 事件及 id，携带动作、对象引用、修订、来源和时间。收片字节进度通过无 id 的 latest 事件覆盖最新值，不增加业务修订或事件序号。SSE 不传完整工作流、外部 history、日志或媒体 base64；媒体通过独立内容端点读取。

网页先取快照，再从其游标订阅；重连重复此过程，并忽略已包含在快照中的事件。断连只提示最后已知状态可能过期，保留已有播放器，不把运行改成失败。正常本机事件刷新目标为持久化后 3 秒以内。LAN 开放及第二设备实测属于后续 M4，当前仍仅监听回环地址。

逐段审片按输入视频与输出槽位组织候选；选中片段和版本后，事件刷新保留选择和播放器。详情提供输入/原片、候选、检查结果、Run、图哈希、内容哈希、目标及外部回执。原始下载与播放代理使用独立引用；`GET /api/versions/{version_id}` 返回版本详情和时间映射状态。

原片与渲染片共用播放/暂停、进度条和上一帧/下一帧按钮，两侧默认静音。以原片参考为主时钟，用 requestAnimationFrame 检查时间差，超过 80 ms 时校正渲染片；任意一侧缓冲或定位未完成时暂停两侧，双方就绪且用户仍要求播放时继续。用户暂停或截图会清除自动续播意图；切换候选清理旧播放器的事件和动画回调。按双方可对照的较短时长结束，保留结束位置供逐帧查看，点击重播从片段起点开始。

逐帧按钮按候选实际 FPS（包括分数帧率）前后移动一个帧位置，操作后保持暂停；拖到两帧之间时按当前所在帧计算。帧率未知时禁用逐帧按钮，不默认假设 24 fps。浏览器媒体解码与 80 ms 纠偏属于时间联动，不承诺两路视频硬件级逐帧锁定。

自定义配方可在视频输出中声明 `time_mapping: {input_slot: video, mode: identity}`，表示保留所选输入的时间顺序与速率。核对输入/输出时长及 FPS 后，平台累加显式片段的 start_seconds，将候选时间换算到完整原片时间。无声明或声明不符合媒体检查时（包括当前 H3），改用输入片段自身从 0 秒开始的相对时间对照，仍提供共用控制、缓冲联动与逐帧按钮。面板明确显示“按时间对照，不保证动作逐帧一致”。时长相同不证明生成动作逐帧对应，也不将未知映射升级为已知。

反馈始终保存候选时间。只有已知映射才填写 original_range；按相对时间联动时，该字段仍为空，不能把用户在面板上的联动操作当成原片映射证据。

反馈保存具体版本、候选时间范围、可用时的原片范围、备注、截图引用与归一化矩形。网页可截取已加载候选的当前帧，上传最长边不超过4096像素的PNG/JPEG（最多8MiB），并在截图上拖拽圈选。截图通过独立URL读取，事件和MCP只传引用。反馈条目可定位回版本时间并查看保存的圈选。

“需要修改”只在版本属于当前有效方案时，和关联任务的 review_hold 同事务保存；其他任务继续执行，已写 intent 的运行继续对账和收片。普通备注和旧方案的反馈不会挂起当前方案；普通恢复派发不会解除审片挂起。Agent 标记 addressed 只表示已处理，仍需用户明确 verified；网页“确认此反馈已解决”或有用户原话的对话代录会记录验证来源。未提交草稿按版本保留在当前页面会话中；修订冲突时保留文字、截图和圈选，用户核对后可用当前修订重试。

接口：`GET /api/review/items?unresolved=true|false`，截图上传/读取位于 `/api/review/screenshots`；写反馈与状态通过统一的 `/api/execution/command`。MCP `save_feedback`、`update_feedback`、`list_review_items` 使用相同应用用例、修订和幂等回执，不直接操作数据库。


返工通过 `create_plan` 创建同任务的新修订，使用 `feedback_ids` 显式关联反馈；只有该修订生效才将关联反馈记为 addressed 并解除对应挂起。原反馈的方案、版本及原 Run/回执保持不变。需要沿用同一逻辑片段（包括更换素材）的候选时，步骤使用原 `segment_id`；未指定时默认视频资产身份。不同任务的候选分开管理。

沿用原用户指示时，各修订共享 `authorization_id`、累计提交次数和失败停止条件，不能通过重建方案重置额度。指示可收窄；改变指示、扩大素材/目标/配方/参数或增加次数，必须取得明确新用户指示并设置 `new_instruction: true`。该字段是 Agent 对已取得指示的记录，不是自动授权机制。

网页“通过并采用当前候选”保存明确用户决定；对话代录使用 MCP `record_user_decision`，必须带用户原话 `user_statement`。`record_evaluation` 单独记录 Agent 技术评价，不产生采用。采用位置按任务、逻辑片段和输出槽确定；新候选失败不会清除旧采用引用。只有技术检查合格且原件可读的已采用版本进入 `get_delivery_manifest` / `GET /api/review/delivery`，包含原片、输入、目标、图/内容哈希和决定来源。首版交付片段及 JSON 来源清单，不做自动拼接。

生产摘要在各视图常驻，显示本项目生成、收片、待审候选、待复核意见及派发暂停/审片挂起/待核对原因。完整监控、项目队列与最近20条业务活动位于任务视图；平台/Worker、活动运行与收片、各执行端详情默认折叠。监控、候选和反馈共享 `/api/state` 与 SSE，刷新不切换用户选择，也不重建播放器或清空批注草稿。

健康采样间隔5秒、有效期15秒；来源、采集/过期时间及缺项原因可展开查看。平台磁盘空间来自项目所在文件系统，远程 ComfyUI 磁盘空间不因此推断。执行端缺节点回调时只显示最近阶段、自提交意图起的耗时及未知原因；模型加载没有独立回调则不声称能够识别它，也不以静默触发重投。断线保留最后快照并标记可能过期，高级主机指标缺失不会按零或正常显示。监控投影不传完整节点 schema/目录，完整资源由独立查询读取。


MCP 工作控制与网页共用业务修订、游标和命令用例：`get_system_status` 读取共享快照，`list_runs/get_run` 读取运行摘要，`get_collection_status` 读取收片。`pause_plan/resume_plan(plan_id)` 控制有效方案后续派发，暂停随同任务新修订继承；项目 `pause_dispatch/resume_dispatch` 和方案暂停分别解除。`cancel_queued_runs(plan_id,run_ids)` 只取消明确指定且 queued、无 intent 的运行，任意一项不符合就整批拒绝。Worker 领取时在同一事务复查，取消与意图预留只有一方能成功。

`propose_plan` 复用 `create_plan` 创建草稿，不自动生效；参数、素材、目标改变须新修订，旧在途记录不改写。控制回执包含 command_id、revision、event_id、result、受影响运行/步骤 `affected_steps` 与剩余门禁 `control`，重复命令返回原回执。暂停/取消都不调用 ComfyUI 全局中断；已有 intent 继续核对和收片，`resume_collection` 恢复原 Run 收片而不增加生成或额度。


新会话用 `get_context` 读取当前根目录、各类修订、有效方案、授权累计/剩余额度、运行/收片、采用与候选、未解决反馈及监测缺项。业务字段与游标在同一读事务取得，配置/资源各保留自己的修订。`read_events(after,limit)` 支持游标分页，`wait_for_events` 默认20秒、最多25秒/100项，超时不推进游标；停服中断等待，宿主断开不停止Worker，离线事件仍可补读。等待不代表宿主自动继续推理或可被离线唤醒。详细续接、冲突和模块操作见随包 ComfyPilot Skill。

公共目标状态只传指标、能力和节点计数/哈希；完整节点schema由服务端预检使用。媒体和截图、运行graph/history/checks、日志及资源按引用访问；运行摘要的 `references` 提供独立证据 URL，尚未产生的证据明确不可用。事件流不包含大块媒体或完整工作图。

## 工作台视图与第一批 UI 优化

默认进入审片，顶部导航提供审片、任务、素材和项目四个视图；`#review`、`#tasks`、`#assets`、`#project` 支持直接定位与浏览器前后退。LAN 仅显示审片与只读任务监控，不能通过手写管理视图地址获得管理入口。

- 项目：项目目录/服务元数据、设置/执行端、模块/配方资源与受管副本维护。

## 第三批：手机专注审片与预览时间轴

手机默认显示候选结果，使用“结果 / 原片 / 对照”切换画面；对照模式两路并排。两个 video 始终挂载，复用原来的共用播放条、缓冲联动和实际 FPS 逐帧控制。切换不重建媒体、不清空草稿；桌面继续双路。手机头部与单片段导航压缩，核心按钮至少 44 px，播放与决定区域滚动到顶部时吸附；采用按钮文字简化，但请求、门禁、幂等和用户明确决定规则保持。按时间对照，不保证动作逐帧一致。

候选列表默认折叠，展开可看真实缩略图、收片时间、执行端、技术检查、采用/拒绝和待复核状态。点击只选择候选，手机随后收起列表；切换清理旧播放器，但按候选区分的反馈草稿、截图与圈选仍保留。列表最多占 200 px 并内部滚动，不为每张卡加载一个视频。此批仍沿用服务端既有快照范围，未新增候选分页。

候选、原片参考和输入视频提供真实 poster；版本预览优先使用已有播放代理，原片依据已核实映射偏移取帧，未知映射使用输入片段起点。JPEG 最多 480×270，项目缓存按需生成，失败清理临时文件；缩略图失败显示“预览不可用”，仍可播放媒体。缓存可重建，不成为素材/版本，不改原文件或收片状态。接口与约束见[媒体说明](media-assets.md)。

反馈时间轴从现有共享快照显示当前候选的点和时间区间，分别标注未处理、待验证、已验证，并显示共同播放游标。每条可点击区域至少 44 px；点击先暂停两路再定位到候选秒数，打开原反馈面板，保留草稿、截图和圈选。时间轴只定位，不保存反馈、不改变 addressed/verified、不推算 original_range。范围超过双方可对照时长时明确提示，完全超出部分不能定位，反馈本身仍可在侧面板读取。

2026-10-29 验证使用禁用执行端且暂停派发的新 UUID 项目恢复副本，复用已有真实 H3 样片，不再次生成或采用。三档 1440×900、768×1024、390×844 无横向溢出，折叠候选时采用/拒绝/反馈入口在对应首屏内。实际点击候选按钮、手机画面切换、逐帧、播放中反馈定位、侧面板焦点/Esc、跨候选及跨页草稿/截图/圈选保持均复验；另拦截视频验证未加载时 poster 可读，拦截预览验证缩略图失败降级，模拟短参考元数据验证超范围提示与裁剪。浏览器模拟不等于实体手机、Safari 或完整辅助技术验收，原真实环境保留项继续保留。最终工程与安装验证见 [M4 补验 E17](m4-validation.md)。
