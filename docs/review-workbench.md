# 实时审片与协作

平台保存业务状态后，在同一 SQLite 事务中追加单调递增的业务事件。`GET /api/state` 在同一读取事务中返回业务修订、事件游标、任务、方案、运行和可审版本。`GET /api/events?after=0&limit=50` 按游标补读，每页最多 100 条；返回的 cursor 是本页实际读取位置，has_more 表示仍需补读。

`GET /api/events/stream?after=<cursor>` 提供 SSE。持久变化使用 business 事件及 id，携带动作、对象引用、修订、来源和时间。收片字节进度通过无 id 的 latest 事件覆盖最新值，不增加业务修订或事件序号。SSE 不传完整工作流、外部 history、日志或媒体 base64；媒体通过独立内容端点读取。

网页先取快照，再从其游标订阅；重连重复此过程，并忽略已包含在快照中的事件。断连只提示最后已知状态可能过期，保留已有播放器，不把运行改成失败。正常本机事件刷新目标为持久化后 3 秒以内。LAN 开放及第二设备实测属于后续 M4，当前仍仅监听回环地址。

逐段审片按输入视频与输出槽位组织候选；选中片段和版本后，事件刷新保留选择和播放器。详情提供输入/原片、候选、检查结果、Run、图哈希、内容哈希、目标及外部回执。原始下载与播放代理使用独立引用；`GET /api/versions/{version_id}` 返回版本详情和时间映射状态。

需要同步对比的自定义配方，可以在对应视频输出中声明 `time_mapping: {input_slot: video, mode: identity}`，表示保持所选视频输入的时间顺序与速率。收片后还需核对输入/输出时长与 FPS；符合时，平台累加显式片段的 start_seconds，把候选时间换算到原片时间，并同步播放、暂停与定位。未知映射只提供普通并排参考。H3 使用视频作为参考条件，当前没有保留逐帧时间轴的声明，因此不自动开启同步，也不能靠相同时长推断逐帧对应。

反馈保存具体版本、候选时间范围、可用时的原片范围、备注、截图引用与归一化矩形。网页可截取已加载候选的当前帧，上传最长边不超过4096像素的PNG/JPEG（最多8MiB），并在截图上拖拽圈选。截图通过独立URL读取，事件和MCP只传引用。反馈条目可定位回版本时间并查看保存的圈选。

“需要修改”只在版本属于当前有效方案时，和关联任务的 review_hold 同事务保存；其他任务继续执行，已写 intent 的运行继续对账和收片。普通备注和旧方案的反馈不会挂起当前方案；普通恢复派发不会解除审片挂起。Agent 标记 addressed 只表示已处理，仍需用户明确 verified；网页“确认此反馈已解决”或有用户原话的对话代录会记录验证来源。未提交草稿按版本保留在当前页面会话中；修订冲突时保留文字、截图和圈选，用户核对后可用当前修订重试。

接口：`GET /api/review/items?unresolved=true|false`，截图上传/读取位于 `/api/review/screenshots`；写反馈与状态通过统一的 `/api/execution/command`。MCP `save_feedback`、`update_feedback`、`list_review_items` 使用相同应用用例、修订和幂等回执，不直接操作数据库。
