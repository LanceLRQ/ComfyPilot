# 大文件收片与监测并发补验

日期：2026-10-29。对应 AC-35；验证自动收片和监测在真实大文件传输、解码、代理及平台重启时的并发行为。

## 测试边界

使用 FFmpeg 生成 1,024×576、24 fps、400 帧、约 16.67 秒的 FFV1/Matroska 噪声视频。每份实际 320,095,880 字节（约 305.27 MiB），强制走完整解码与 H.264 浏览器代理路径；协议声明中的测试文件扩展名为 .mp4，容器按内容探测。该素材不评价人物替换画质，也没有原片时间轴对齐声明。

本机测试使用实际扩展路由，远程测试使用已升级的生产 ComfyUI 素材桥接、真实 input/output 根与 LAN 传输。输出由测试通过已授权管理通道放入本次新 UUID/Run 的专属命名空间；输入真实上传。生成提交、queue、history 与测试节点声明来自受控协议端，只有一次受控 POST /prompt，**不调用真实 GPU 生成**。远程场景的 /system_stats 读取真实 ComfyUI，本机场景的指标值来自协议端；两者的采集调度、API 响应和 Worker 心跳均为真实进程测量。

测试通道每 MiB 人为停顿 80 ms，延长传输观察窗口；不是网络吞吐基准。浏览器和 MCP 不保持在线，独立 API/Worker 自动收片；观测程序每约 200 ms 查询一次 /api/state。连续场景不干预；重启场景在已传输至少 8 MiB 后真正停止、再启动同一项目平台，按原回执恢复。

## 验收方法

- 收片经历 transferring、checking、proxy，完整解码 400 帧后只有一个 ready 版本，原件大小正确且浏览器代理为 H.264。
- 每场景使用次数为 1，额外 POST /prompt 为 0；重启后重新传输而非生成，总下载请求由 1 次变为 2 次。当前不承诺字节续传。
- 至少观察 4 个不同 Worker 心跳，最大间隔低于 10 秒；至少 4 个目标指标采样时间，最大间隔低于 15 秒，已有指标不进入 stale；API 单次观测低于 3 秒。允许启动/重启后尚未采到值时显示 unknown。
- 测试结束停止本次平台；保留源码外原始采样及本地原件。生产 ComfyUI 保持在线，原用户项目及采用作品不参与测试。

以下实测只覆盖这一尺寸和短时限速负载，不代表 64 GiB 上限、长时间稳定性或更多并发项目的保证。

## 复验

先完成锁定依赖、FFmpeg/ffprobe/libx264 和 make check。在仓库根目录运行：

```sh
COMFYPILOT_PRESSURE=1 uv run --locked --extra dev pytest tests/test_collection_pressure.py -q -s
```

默认 make check 跳过这两项，避免每轮回归生成大文件。显式运行会创建独立 pytest 项目，不使用用户的创作目录；每个用例生成 pressure-result.json，记录结果和全部采样。若自定义 --basetemp，只能指定新的专用临时目录，pytest 会管理和清空该路径。

远程复验另需用户已授权的 SSH 通道与 ComfyUI output 根，三者必须属于同一部署；替换示例变量：

```sh
COMFYPILOT_PRESSURE=1 \
COMFYPILOT_PRESSURE_BRIDGE=http://comfy-host:8188 \
COMFYPILOT_PRESSURE_SSH=user@comfy-host \
COMFYPILOT_PRESSURE_OUTPUT=/absolute/comfy-output \
uv run --locked --extra dev pytest tests/test_collection_pressure.py -q -s
```

远程测试只在新 UUID/Run 下写入测试输出，不负责静默删除。结束后如需回收空间，按[素材维护](asset-cleanup.md)停止测试方案、明确拒绝合成测试候选，预览并执行仅含该项目已登记副本的清单；核对本地原件与既有媒体哈希。本轮已实际完成该清理闭环，见[桥接升级补验](remote-assets.md)。记录、媒体、私有地址及原始日志留在源码外，不上传看板或开源仓库。
